一、核心知识精讲

1.1 拒绝采样（Rejection Sampling）深度解析

拒绝采样在本项目中是数据质量的核心守门人。它不只是"过滤错误"，而是一套完整的数据价值评估体系。

为什么难度分层有效？——对标教育学中的"最近发展区"（Zone of Proximal Development）理论：太简单的任务没有学习价值（模型已经会了），太难的任务学不到东西（梯度噪声太大），只有"当前能力边界附近"的任务才能有效推动能力提升。

1.2 LoRA 微调原理与超参选择

LoRA（Low-Rank Adaptation）核心思想：冻结预训练权重 W，额外训练一对低秩矩阵 A (r×d) 和 B (d×r)，使得 W' = W + BA。参数量从 d×d 降到 2×d×r（r << d），训练开销大幅下降。

秩 r 的选择依据：

r 值参数量适用场景风险
4-8极少（<0.1%）简单适配（格式学习、风格迁移）容量不足，复杂推理学不进去
16-32中等（~0.3%）复杂任务（推理、知识注入）平衡点，大部分场景首选
64-128较多（~1%）接近全参微调效果过拟合风险增大，训练成本接近全参
在我们项目中，最终产出使用的是全参 SFT（不用 LoRA），因为目标是让模型获得全新的慢思考范式，这需要较大的权重更新幅度。但迭代过程中我们用 LoRA（r=32）做快速实验验证数据质量和训练策略，确认有效后再切全参。LoRA 实验的周期是全参的 1/5，极大加速了迭代。

1.3 vLLM 加速原理与 PagedAttention

vLLM 是当前最高效的 LLM 推理引擎之一，核心创新是 PagedAttention——把操作系统的虚拟内存分页思想应用到 KV Cache 管理。

    subgraph Traditional["传统方案: 连续 KV Cache"]
        T1["请求1: [████████░░░░░░░░]
预分配最大长度，大量浪费"]
        T2["请求2: [████░░░░░░░░░░░░]
短序列更浪费"]
    end
    subgraph Paged["PagedAttention: 分页 KV Cache"]
        P1["请求1: [页1][页2][页3]... 按需分配"]
        P2["请求2: [页1][页2]... 用多少分多少"]
        P3["物理页池: 共享+复用"]
    end

PagedAttention 解决的核心问题：传统 KV Cache 为每个请求预分配最大序列长度的连续显存，导致：

  1. 内部碎片：实际序列远短于最大长度，大量显存被预留但未使用（浪费率 60-80%）
  2. 外部碎片：不同请求的 KV Cache 大小不一，长请求结束后留下的"空洞"无法被短请求利用
  3. 无法共享：Beam Search 或并行采样时，多个候选序列的公共前缀重复存储

PagedAttention 的解决方案：

  1. 把 KV Cache 切成固定大小的页（Block），每页存若干 Token 的 KV 向量
  2. 用页表（Block Table）维护逻辑页→物理页的映射，支持非连续存储
  3. 按需分配：序列增长时动态分配新页，序列结束时回收页到空闲池
  4. 支持 Copy-on-Write：并行采样时共享前缀页，分叉时才复制

在我们项目中的应用：评测阶段需要对数千条测试样本做推理，长 CoT 的输出长度不可预测（从几十 Token 到几千 Token），传统方案要么按最大长度预分配（浪费显存、batch size 极小），要么截断（丢失推理链）。vLLM 的 PagedAttention 让我们能动态适配不同长度的输出，batch size 提升 3-4 倍，评测吞吐量显著提高。

1.4 MathVista / MMVet 评测体系

基准测试内容评测维度指标含义
MathVista数学视觉推理（几何、图表、统计图、函数图）GPS（几何问题解决）、MWP（数学应用题）、TQA（图表问答）、VQA（视觉问答）整体准确率：模型在所有数学视觉任务上的平均正确率

14.6% / 16.4% 提升的核心归因：

  1. 推理链质量（主因，贡献 ~60%）：高质量的长 CoT 让模型学会了逐步推理而非直接猜答案。MathVista 的提升尤其明显，因为数学题最依赖中间推理步骤。
  2. 拒绝采样（贡献 ~25%）：过滤掉推理链有误的脏数据，避免模型学到错误的推理模式。对比实验：无拒绝采样时 MathVista 只提升 ~8%。
  3. 反思能力（贡献 ~15%）：保留有效反思样本后，模型具备了自我纠错能力，尤其在 MMVet 这类综合任务上表现突出——模型会在推理过程中发现矛盾并修正。

二、面试易错点

错误 1：说"LoRA 比全参微调效果差"。LoRA 在特定场景下可以接近全参效果（尤其是格式学习、知识注入），但在"让模型学会全新范式"这种大幅度能力变更场景下确实不如全参。要讲清楚为什么你最终选了全参，而不是一刀切地评价两者优劣。
错误 2：把 vLLM 说成"就是加了 Flash Attention"。vLLM 的核心是 PagedAttention（解决显存管理问题），Flash Attention 是计算加速（IO-aware 的融合算子减少 HBM 读写）。两者正交互补，vLLM 内部也集成了 Flash Attention，但核心贡献是不同的。
错误 3：被问"14.6% 是绝对提升还是相对提升"时含糊其辞。我们的表述是相对提升：(74.5-65)/65 = 14.6%。绝对提升是 9.5 个百分点。面试时要主动说清楚口径，显示严谨性。

三、满分逐字稿

Q6：拒绝采样的策略是什么？如何定义「不合格推理链」？

满分逐字稿

面试标准回答

我们的拒绝采样不是简单的"答案对不对"过滤，而是一个多维度的数据质量评估 + 难度分层体系。

采样策略：每条原始数据调用慢思考 API 生成 5 次，得到 5 组 [推理链 + 答案] 配对。对每组分别做答案正确性和推理过程正确性的交叉核验。保留规则是 answer 和 thinking 都被判定正确的组才能进入训练集。

难度分层：这是整个策略最精髓的部分。5 次生成中答错的次数就是该条数据的难度等级：0 次答错 = 难度 0（简单），1 次 = 难度 1，以此类推。我们保留难度 0-4 的所有数据，但剔除 5 次全错的（难度 5）。理论依据是教育学中的"最近发展区"——全对的太简单、全错的太难，都不是最优训练数据。后来我们做了消融实验，验证了只保留难度 1-3（中等难度）的效果最好，但出于数据量考虑最终保留了 0-4 的全部。

"不合格推理链"的五维度定义：第一，答案错误——最终答案与标准答案核心信息不一致；第二，逻辑断裂——推理步骤之间存在跳跃或矛盾，前提不支持结论；第三，重复输出——推理过程出现大段重复文本（通过 ngram 重复率检测），这通常意味着模型陷入了生成循环；第四，无效反思——模型进入了"反思循环"，反复质疑自己但不产生新信息，不改变最终结论；第五，格式异常——无法提取到标准格式的答案，或输出被截断导致推理链不完整。

实际数据显示：LLaVA-COT 拒绝率 15.34%，R1Onevision 拒绝率 6.89%（质量高），FineVision 拒绝率高达 69.97%（题目难度大）。FineVision 高拒绝率不意味着数据集差——恰恰说明它包含了大量高难度题目，保留下来的 30% 是真正能推动模型能力边界的高价值数据。

追问防御

Q: 全对的为什么还保留？不是说太简单没价值吗？

全对的数据训练价值确实低，但完全剔除会导致训练数据的难度分布严重偏右（全是难题），模型可能在简单题上反而退化。我们保留难度 0 的数据是为了维持能力基线——让模型在学习"深度推理"的同时不忘"简单题也要答对"。实际训练时我们对难度 0 做了降采样（权重降低），相当于 soft rejection。

Q: 无效反思和有效反思怎么区分？

关键判断标准：反思是否改变了推理方向或修正了错误。有效反思的特征是：发现了前面推理的具体错误 → 给出修正方案 → 推导出不同的（更正确的）结论。无效反思的特征是：反复说"让我再想想"但推理路径没变，或者质疑已经正确的步骤导致"正确→怀疑→还是原来的答案"的无用循环。我们发现 API 返回的慢思考中约 50% 包含反思，其中约一半是无效的。不筛选直接训练会导致模型学到"反复纠结"的坏习惯，输出重复率飙升。

Q7：LoRA 微调原理，秩的选择依据？你调了哪些超参？

满分逐字稿

面试标准回答

LoRA 的核心思想是：大模型微调时权重的变化量 ΔW 是低秩的——即用两个小矩阵的乘积就能近似表示。

数学上：冻结原始权重 W ∈ R^(d×d)，额外训练 A ∈ R^(r×d) 和 B ∈ R^(d×r)，推理时 W' = W + α·BA/r，其中 α 是缩放系数。可训练参数从 d² 降到 2dr，当 r=16、d=4096 时参数量降低到原来的 0.8%。

秩 r 的选择依据：r 的本质是"你允许模型改变多少"。低秩（r=4-8）适合轻量适配——让模型学新格式、新语气，不改变核心能力；中等秩（r=16-32）适合能力注入——让模型学会新的推理模式或领域知识；高秩（r=64+）接近全参效果。选择 r 的经验法则：任务越复杂、与预训练分布差异越大，需要的 r 越大。

我们项目的超参选择：

快速实验阶段用 LoRA：r=32、α=64（α/r=2 是常用的缩放比）、target modules 选 q_proj + v_proj + k_proj + o_proj（所有 attention 投影层）、dropout=0.05、learning rate=2e-4、batch size=32、warmup ratio=0.03。

最终训练用全参 SFT：因为我们的目标是让模型学会一种全新的输出范式（从"直接回答"到"先想再答"），这是对模型行为的根本性改变，不是简单的知识注入或格式适配。LoRA 实验证明了数据质量 OK 后，切全参能多提 3-4 个绝对百分点。全参超参：learning rate=1e-5（比 LoRA 小一个量级，避免灾难性遗忘）、cosine scheduler、2 epoch、gradient accumulation=4。

为什么只训 2 个 epoch：长 CoT 数据信息密度高（每条样本包含完整推理链，Token 长度 500-3000），2 epoch 足够模型学会范式。3 epoch 开始出现过拟合——在训练集 loss 继续下降但验证集指标不再提升，推理输出开始出现训练数据的"模板化"痕迹。

追问防御

Q: 为什么不用 QLoRA？

QLoRA 是把基础模型量化到 4bit 再做 LoRA，进一步降低显存。我们快速实验时其实也用了 QLoRA（NF4 量化 + double quant），效果和标准 LoRA 差距不大（~1% 以内）。但最终产出用全参，QLoRA 只用在前期验证阶段。如果算力受限必须用 LoRA 交付，我会选择标准 LoRA + bf16 而非 QLoRA，因为 4bit 量化在长序列生成时有轻微的精度损失，而我们的输出序列很长。

Q: 怎么判断 LoRA 的 target modules 该选哪些层？

经验规则：(1) attention 的 q/k/v/o 投影是"必选"，因为 attention 是信息路由的核心；(2) MLP 的 gate/up/down 投影是"可选"，加上后参数量翻倍但效果提升 1-2%；(3) embedding 层和 LM head 一般不用 LoRA——这两层直接操作词表，低秩假设不太成立。我们选了 q+k+v+o 四个 attention 层，是准确率和训练速度的平衡点。

Q: 灾难性遗忘怎么处理？

三个策略：(1) 低学习率（1e-5），减缓权重偏移；(2) 只训 2 epoch，不过度拟合到新数据；(3) 训练数据中混入了一部分通用指令数据（虽然主体是 CoT 数据），保持模型的通用对话能力。另外我们在评测时不只看 MathVista/MMVet 的提升，还会抽测模型在通用 benchmark 上有没有退化。

Q8：vLLM 加速原理，PagedAttention 核心机制？

满分逐字稿

面试标准回答

vLLM 的核心贡献是用 PagedAttention 解决了 LLM 推理中 KV Cache 的显存管理问题——这是自回归生成的瓶颈所在。

先说问题：Transformer 自回归生成时，每生成一个新 Token 都需要与之前所有 Token 做 Attention 计算。为了避免重复计算，系统会把之前 Token 的 Key/Value 向量缓存下来，这就是 KV Cache。问题是：传统方案为每个请求预分配最大序列长度的连续显存（比如 2048 Token × KV 维度）。实际序列可能只有 200 Token，剩余 1848 个位置的显存被白白浪费——浪费率高达 60-80%。而且不同请求长度不一，内存碎片严重。

PagedAttention 的核心机制，借鉴了操作系统虚拟内存分页：

第一，分页存储：把 KV Cache 切成固定大小的页（Block），每页存 16 或 32 个 Token 的 KV 向量。页不需要物理连续——通过页表（Block Table）维护逻辑页到物理页的映射。

第二，按需分配：序列开始时只分配第一页，每生成 16 个 Token 分配一个新页，序列结束时回收所有页到空闲池。显存利用率从 20-40% 提升到接近 100%。

第三，Copy-on-Write 共享：并行采样（比如 Beam Search 或我们的 5 次重复生成）时，多个候选序列共享公共前缀的 KV Cache 页。只有当某个候选序列开始分叉时，才复制该页做独立修改。这在我们的场景下特别有用——同一条数据生成 5 次，它们共享 Prompt 部分的 KV Cache，显存开销接近 1 次而非 5 次。

在项目中的应用：评测阶段我用 vLLM 搭建了离线推理服务。由于长 CoT 输出长度不可预测（从 50 到 3000+ Token），传统方案按最大长度预分配的话 batch size 极小（4-8），吞吐量很低。PagedAttention 让我们能用动态 batch size（16-32），对短输出早释放显存给下一个请求，评测速度提升约 3-4 倍。配合 continuous batching（一个请求生成完毕立即腾出位置给队列中的新请求），整体 GPU 利用率从 ~40% 提升到 ~85%。

追问防御

Q: PagedAttention 和 Flash Attention 是什么关系？

两者解决不同层面的问题。Flash Attention 是计算层优化——把 QKV 计算拆成 tile，利用 SRAM 的高带宽做分块计算，减少对 HBM 的读写次数，是 IO-aware 的算子融合。PagedAttention 是内存管理层优化——解决 KV Cache 怎么存、怎么分配、怎么共享的问题。两者正交：vLLM 内部既用 PagedAttention 做 KV 管理，又用 Flash Attention 做 Attention 计算加速。

Q: 你用 vLLM 部署时遇到过什么坑？

主要两个：(1) 多模态模型的 image encoder 部分 vLLM 支持有限——当时我们用的模型版本需要自己写 image preprocessing 的 adapter，把图片预处理逻辑对齐到 vLLM 的 pipeline 里；(2) 长 CoT 输出时偶尔触发 OOM——虽然 PagedAttention 按需分配，但如果 batch 内所有请求同时生成很长的输出，物理显存还是会不够。我加了显存监控 + 动态调整 max_num_seqs 的逻辑作为安全兜底。

Q9：MathVista、MMVet 评测指标含义，提升 14.6%、16.4% 的核心原因是什么？

满分逐字稿

面试标准回答

先说清楚指标口径：14.6% 和 16.4% 都是相对提升（relative improvement），不是绝对百分点。

MathVista：base model 得分 65.0，优化后 74.5，绝对提升 9.5 个百分点，相对提升 (74.5-65)/65 = 14.6%。MMVet：base model 得分 59.1，优化后 68.8，绝对提升 9.7 个百分点，相对提升 (68.8-59.1)/59.1 = 16.4%。

两个基准的评测含义：

MathVista 测的是数学视觉推理——模型需要理解图表、几何图形、统计图后做数学推理。评测方式是精确匹配（选择题/数值题有标准答案）。它直接衡量"逐步推理能力"，是慢思考最该提升的指标。

MMVet 测的是综合多模态能力——包含识别、OCR、知识、空间理解、数学、语言生成六个维度的集成。评测方式是 GPT-4 打分（0-1 连续分值），评估回答的准确性、完整性和表达质量。它衡量的是模型的"综合素质"，提升说明慢思考不只改善数学推理，还连带提升了其他能力。

提升的核心归因（通过消融实验验证）：

第一，推理链质量是主因，贡献约 60%。对比实验：用同样的数据量但不带慢思考（只用快思考直接回答做 SFT），MathVista 只提升 3-4 个百分点。说明提升主要来自"让模型学会逐步推理"而非"喂更多数据"。

第二，拒绝采样贡献约 25%。对比实验：不做拒绝采样直接用所有生成数据训练，MathVista 只提升 ~8%。有 6-7% 的提升来自过滤掉了推理链有错的脏数据——这些脏数据不仅没帮助，还会教会模型"错误的推理方式"。

第三，有效反思保留贡献约 15%。对比实验：把所有包含反思的数据删除 vs 保留有效反思，后者在 MMVet 上多提升了约 2 个绝对百分点。这说明"发现错误并修正"的能力对综合任务尤其有价值——因为 MMVet 包含开放式问题，模型需要在回答过程中自我纠正。

追问防御

Q: 你的 base model 是什么状态？是从零预训练的还是已经经过 SFT 的？

Base model 是讯飞的 ipt-13B，已经经过了通用 SFT（会做基本的指令跟随和多模态问答），但没有经过慢思考训练——它只会"快思考"直接回答。我们的工作是在这个基础上继续 SFT，让它具备慢思考能力。所以 14.6% 的提升是"在已有不错能力的模型上再提升"，不是从一个很弱的起点开始。

Q: 你确定没有数据泄露？训练集和测试集有重叠吗？

这是我们数据选型时的第一原则。具体做法：(1) 查看每个数据集的数据来源说明，确认图片和问题不来自 MathVista/MMVet 的测试集；(2) 对图片做 perceptual hash（感知哈希）去重，确保没有相同或近似图片出现在训练和测试中；(3) 对问题文本做 n-gram 相似度检查。FineVision 体量大时我们特别谨慎，排除了多个可能与评测集重叠的子集。

Q: MMVet 用 GPT-4 打分，这个评测可靠吗？

GPT-4 评分的 inter-annotator agreement 在 MMVet 论文中报告了与人类评分的相关系数（~0.85），是可接受的。但确实存在系统偏差——GPT-4 倾向于给"格式好、表述完整"的回答更高分，即使内容准确度相同。我们的慢思考模型输出的回答通常更结构化（因为经过了推理链整理），这可能贡献了一部分 MMVet 的提升。不过我们也在 MathVista 这个精确匹配基准上有 14.6% 提升，说明核心推理能力确实提高了，不只是"答案写得好看"。

Q10：多模态长推理目前仍存在的短板是什么？你有什么优化思路？

满分逐字稿

面试标准回答

多模态长推理目前有四个核心短板，我按严重程度排列，每个都说解决思路。

短板一：推理效率与质量的矛盾。长 CoT 意味着更多 Token 输出，推理延迟成倍增加。一条需要 2000 Token 思考过程的题目，比直接回答慢 10-20 倍。在实际应用中用户可能等不起。优化思路：(1) 动态 CoT 深度——简单问题用短 CoT 甚至跳过思考，复杂问题才展开长推理，通过路由器模型或 confidence score 判断问题难度；(2) 推测解码（Speculative Decoding）——用小模型快速生成 draft，大模型并行验证，加速长序列生成。

短板二：视觉推理中的细节丢失。视觉编码器（ViT）的分辨率限制导致高分辨率图片中的小细节被压缩丢失。即使推理链完美，如果第一步"看图"就看错了，后续推理再深也是错的。我们在 MathVista 的几何题上观察到这类失败——模型把 30° 角看成 45° 角，后续推理过程完全正确但答案就是错的。优化思路：(1) 动态分辨率——对需要精细观察的区域做 crop+zoom 后重新编码；(2) 多尺度特征融合——保留低分辨率全局信息的同时注入高分辨率局部特征。

短板三：反思失控。这是我们在项目中直接遇到的问题——模型学会反思后，有时会过度反思，不断质疑正确的步骤，输出陷入"正确→怀疑→重来→还是正确→再怀疑..."的死循环，导致输出极长且重复。这也是为什么我们要专门做"反思有效性筛选"。优化思路：(1) 在训练数据中控制反思比例和长度分布；(2) 加入反思终止训练——让模型学会"验证通过就停止反思"；(3) 推理时加 repetition penalty 和 length penalty 做工程约束。

短板四：跨模态推理链的可验证性差。纯文本推理链每一步都可以逻辑验证，但多模态推理链中"我看到图中有一个三角形"这一步很难自动验证——Process Reward Model 无法像文本推理那样逐步打分。这导致 RL 在多模态场景的应用远比纯文本困难。优化思路：(1) 引入视觉 Grounding——推理链中每次引用图像信息时标注 bounding box 坐标，使视觉信息可追溯可验证；(2) 构建多模态 PRM（Process Reward Model）——这是学术界正在攻关的方向，需要大量带有逐步标注的多模态推理数据。

如果让我选一个最值得投入的方向，我选动态 CoT 深度——它既解决效率问题（简单题不浪费计算），又间接减少反思失控（限制了最大推理长度），而且实现路径清晰：训练一个轻量级路由器预测问题难度，难度低走快思考路径，难度高走慢思考路径。

追问防御

Q: 你说的"动态 CoT 深度"怎么训练路由器？

可以用我们现有的难度标注数据来训练：我们已经为每条数据标注了难度等级（0-4），这本身就是一个 difficulty predictor 的训练集。路由器可以是一个小型多模态模型（比如 1B 参数），输入图片+问题，输出难度预测，决定后续用快思考还是慢思考。训练成本极低，推理时增加的延迟可忽略（小模型前向一次 <50ms）。

Q: 现在学术界有什么更前沿的方向？

几个值得关注的方向：(1) OpenAI o1/o3 的方案——用 RL 直接在推理链上做优化，但目前多模态版本效果还不如纯文本；(2) Process Reward Model——对推理链每一步打分而非只看最终答案，能更精准地指导训练；(3) Tree of Thought——不是线性推理链而是树状搜索，每步探索多条路径再选最优，但计算开销巨大；(4) 多模态 Agent 搜索——让模型在推理过程中主动"放大看"图片局部、调用计算器等工具辅助推理，不再是纯粹的语言推理。

Q: 如果给你更多时间和资源，你会怎么改进这个项目？

三个优先级：第一，构建多模态 PRM 做 RL 训练——目前蒸馏路线的天花板就是 teacher 模型的能力，RL 能突破这个上限；第二，引入动态 CoT + 路由器，让模型"该想的时候想、该快答的时候快答"；第三，扩展到视频理解场景——视频帧序列的时序推理比静态图片更需要长推理链，是慢思考价值最大的新方向。

四、飞书文档改进建议
