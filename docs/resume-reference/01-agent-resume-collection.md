## 简历三（6.28，27 届）⭐ 高质量参考

![简历截图](https://internal-api-drive-stream.feishu.cn/space/api/box/stream/download/authcode/?code=NjMyNjYzOTUyMmY4NmY3MzM2Yzg4MjZlNTU1OWUxOTRfNmNjMzZhN2YyNGU0ZTJhYTRjMmM3YTZkNjFlMjE0NWRfSUQ6NzY2MjI3Nzg2OTM5MTQ4MjEzOF8xNzg0MDE2NjYwOjE3ODQwMjAyNjBfVjM)

### 评论（重点）

> 这份简历虽然项目深度和质量也属于中等水平，但已经和套模板的项目高下立判了。

**项目一：Coding Agent**

| # | 评论要点 | 类型 |
|---|---------|------|
| 1 | 堆砌技术栈，runtime 层、协作层两个意义不大可以略写，因为这是行业基础操作看不出来水平高低 | ❌ 缺点 |
| 2 | **评测与回放层很有意思**：证据系统是能显著提升长程工作与强推理任务的质量的，谷歌也发过论文 | 👍 亮点 |
| 3 | **回放层很类似案例设计**，也符合 AI 开发的原则，最小改动原则以确保任务驱动能力，这个设计的非常好 | 👍 亮点 |
| 4 | Role/Skill 层这里也有点套路化，不提 | ⚠️ 一般 |
| 5 | **产品化落地这块解决了核心问题**：不是和 Codex 竞争，而是去做垂类的 roles 和 skill，走专家知识沉淀的路线，这样不就事实上解决了和主流 coding 的竞争 | 👍 亮点 |

**项目二：记忆/RAG 项目**

| # | 评论要点 | 类型 |
|---|---------|------|
| 1 | 实际上不是 RAG 项目，但**记忆和 RAG 面临的都是同样的召回问题** |  洞察 |
| 2 | **长期记忆在开发特征上是和 RAG 相当接近的**，那你的 RAG 是不是从静态变动态就可以写成长期记忆和自进化了？ |  包装思路 |
| 3 | **图谱 + 向量的思路很有意思**：一个建立逻辑一个建立语义，虽然增加了搜索成本，不过有自己的设计和思路 | 👍 亮点 |
| 4 | 后面的建立关系什么的，这不就是一个很不错的项目，不比套开源库的干巴巴的强多少 | 👍 亮点 |
| 5 | 就这两个项目就已经吊打多少简历了，可以对比着好好看一下 | 👍 总结 |

> 技术深度这东西可不是说着玩玩的，agent 开发与设计不是单纯扒点开源库就算会了，这种设计能力很多人压根都意识不到。很多项目只要稍微改改，加点自己的小巧思就是很有意思的东西。扒开源库没问题，然而不去深入思考和学习，在 agent 这个领域始终都慢人一步。
