## 一、简历整体策略

### 1.1 两个项目的定位

| 项目 | 定位 | 证明的能力 |
|------|------|-----------|
| **DM 主站** | 纯后端工程 | Go 工程、高并发、分布式任务调度、微服务、API 网关 |
| **Monet Agent** | AI Agent | Agent 架构、Tool Use、Memory、Prompt、RAG、Multi-Agent |

两个项目加起来覆盖 Agent 方向 JD 要求的 **工程 + AI 两条线**，各归各的真实能力，不硬蹭。

### 1.2 简历排序原则

```
1. 基本信息（姓名/联系方式/学校/学历）
2. 专业技能（语言 + 技术栈，关键词前置）
3. 实习经历（有实习必须先放，无实习跳过）
4. 项目经历（Monet Agent → DM 主站）
5. 竞赛/开源/博客（加分项）
```

**为什么 Monet 放 DM 前面？** 投的是 Agent 岗，Agent 项目是第一相关度。DM 是工程能力背书。

## 二、专业技能怎么写

### 2.1 必须出现的关键字（机器筛选用）

这些词**必须在简历中出现**，否则可能过不了机器筛选：

```
Python, Go, Java, C++  （至少出现你会的）
LLM, Transformer, Agent
RAG, MCP, Function Calling, Tool Use
Planning, Reasoning, Memory
LangChain, Dify, PyTorch
分布式系统，高并发
```

### 2.2 写法建议

**❌ 不要写：**
```
- 熟悉 Python，了解 Go
- 熟悉 LLM 相关技术
- 了解分布式系统
```

**✅ 要写：**
```
- Python（熟练），Go（熟练），Java（了解）
- LLM/Transformer 原理深入理解，熟悉主流 LLM 架构演进
- 熟悉 Agent 核心范式：Planning / Reasoning / Tool Use / Memory / RAG
- 熟悉 MCP 协议、Function Calling、LangChain/Dify 等 Agent 开发框架
- 有分布式系统设计经验，熟悉高并发、消息队列、异步调度
```

**原则：每个技能后面跟一个具体的能力描述或案例锚点。**

## 三、项目经历怎么写

### 3.1 核心写法：STAR + 量化

每个项目按这个结构写：

```
【项目背景】一句话说明项目是什么、解决什么问题
【技术架构】用一句话说清楚技术选型和架构
【核心工作】3-4 条，每条都是 STAR 格式：
  - 做了什么（Situation/Task）
  - 怎么做的（Action）
  - 结果如何（Result）← 必须有量化
```

### 3.2 Monet Agent 项目建议结构

```
Monet — AI 智能体平台 | 核心开发 | 2025.xx - 2026.xx

项目背景：
  网易互娱 AI 美术平台 Monet，基于 LLM 构建智能体，
  为用户提供图像/视频/3D 等 AI 创作能力。

技术架构：
  Python + DeepAgent 框架，集成多模型（文/图/视频/3D/音频），
  支持 Tool Use、Memory、Multi-Agent 协作。

核心工作：
  1. Agent 核心架构：设计并实现 Agent Loop、Tool Calling、
     Memory 管理模块，支持 XX 种工具调用，任务成功率 XX%
  2. 上下文工程：实现长短期记忆系统，结合 RAG 知识库，
     上下文准确率提升 XX%，长对话遗忘率降低 XX%
  3. 多模型调度：统一封装 XX 家 AI 供应商接口，
     支持模型热切换，平均响应延迟 XXms，可用性 99.X%
  4. Prompt 工程：设计面向 XX 场景的 Prompt 体系，
     生成质量评分提升 XX%，用户满意度提升 XX%
```

## 四、从评论中总结的避坑清单

### 4.1 绝对不要做的事

| 坑 | 说明 | 正确做法 |
|----|------|---------|
| **技术名词堆砌** | "我用 Anthropic SDK + ReAct + MCP + LangChain" → 看起来像"我懂 Agent 黑话" | 每个技术名词后面跟"用它解决了什么问题" |
| **只写做了什么** | "负责 Agent 开发" → 换个人来也能写 | 写"用 XX 技术解决了 XX 问题，结果 XX" |
| **套模板项目** | DeepAgents 深度搜索、RAG 问答 → 写的人太多了 | 加点自己的小巧思，做出差异化 |
| **没有量化指标** | "性能提升了很多" → 空洞 | 必须有数字：成功率 XX%、延迟 XXms、提升 XX% |
| **项目没背景** | 面试官不知道这个项目是干嘛的 | 开头一句话交代业务场景和规模 |
| **简历太满** | 写这么满，扫一眼抓不到重点 | 适当留白，重点加粗，一页为佳 |
| **关键词缺失** | 没写 Python/Go/Java → 机器筛不掉你 | 编程语言必须出现在专业技能栏 |
| **后端项目没后端技术** | Agent 项目写满了 AI 术语，后端技术栈空空如也 | DM 项目里把 Go、分布式、高并发写清楚 |

### 4.2 值得学习的好做法

| 做法 | 说明 |
|------|------|
| **有业务背景的项目** | 不是 toy demo，是真实业务场景，有用户量/数据量 |
| **评测体系设计** | 证据系统、回放层、最小改动原则 → 体现设计能力 |
| **垂类定位** | 不和 Codex 竞争，做垂类 roles/skill → 有思考深度 |
| **图谱 + 向量** | 长期记忆用图谱建立逻辑 + 向量建立语义 → 有自己的设计 |
| **RAG 写成长期记忆** | 同样的召回问题，换个角度写成长期记忆和自进化 → 包装思路 |
| **每个技能对应案例** | 面试官一眼看出你能干活 |

```

  - ...

项目经历

    项目背景：...
    技术架构：...
    核心工作：
      1. ...
      2. ...
      3. ...

  DreamMaker 主站 | 核心开发 | 2025.xx - 2026.xx
    项目背景：...
    技术架构：...
    核心工作：
      1. ...
      2. ...
      3. ...

竞赛/开源/博客（可选）
  - ...
```

### 6.3 语言风格

- **动词开头**：设计、实现、优化、构建、主导
- **量化结果**：XX%、XXms、XX 万
- **技术名词自然嵌入**：不是堆砌，是在描述工作时自然带出
- **不用"熟悉/了解"开头**：直接用技能名 + 能力描述
