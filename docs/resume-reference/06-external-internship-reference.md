## 一、重庆懂车族科技有限公司（2025.11 - 2026.04）

业务方向：OKR、战略规划、立项管理等。

### 1. AI 智能问答工作流

基于 Eino 图编排搭建 OKR AI 智能问答系统，实现意图识别、内容解析、能力分流等多个分支；各节点配置专属 Prompt 模板，通过模板变量动态组装上下文，在变量填充阶段并行调用 OKR 详情 RPC 与权限校验接口，聚合业务数据后注入 Prompt 供 LLM 推理。设计 Redis 链表存储结构支撑断点续传，网络中断后后端继续消费 LLM 响应并持久化，用户重连后从断点恢复，将单次问答耗时从 8-9s 压缩至 250ms，同时节省 LLM Token 重复消耗。

### 2. 权限系统迁移（Kani → AuthZ）

主导权限系统从字节 Kani 向懂车帝 AuthZ 迁移，解决 Kani 角色不支持动态筛选（如下级动态变化需手动维护）的痛点。设计权限系统抽象层封装两套实现，采用双读 Diff 策略（单用户实时对比 + 定时任务全量校验），发现不一致时保守返回原系统权限并触发埋点告警，迁移过程用户零感知，保障数据一致性。

### 3. 接口性能优化

通过数据轻重分离、低频字段裁剪、并行处理数据 IO 以及聚合 RPC 调用，将策略树接口、登录信息接口 P99 分别降低约 55% 和 60%。

### 4. OKR 自定义权限体系

参与设计并落地 OKR 四层权限模型（全周期 / 当前周期 / O / KR），支持按部门、上级、具体人员等多维度配置可见性。设计按层级去冗余存储策略，减少冗余数据存储；运行时继承补齐可见性结果。填补懂车帝 OKR 权限治理空白。

## 二、京东科技信息技术有限公司（2026.05 - 2026.08）

### 1. Chain 编排框架（参与设计）

将对话请求拆分为独立步骤（阶段分析 → 知识检索 → Prompt 组装 → LLM 生成等），按业务需求组合执行——串行用于步骤间有依赖的场景，并行链同时发起多个独立 LLM 调用以降低总延迟，流式并行在并行基础上通过 asyncio.Queue 实时输出结果而非等待全部完成，条件分支链路根据运行时条件选择不同处理路径（如命中规则走预设话术、未命中走 LLM 生成）。

### 2. 外呼分阶段对话模块（参与开发）

外呼场景下对话按业务阶段推进（如引导开卡 → 激活额度 → 发起贷款），LLM 可能跳步或跑偏，因此用状态标记锁定当前阶段并注入 Prompt 约束 LLM 按阶段回复；实现规则引擎在满足条件时（如后端检测到额度已出）直接返回预设话术跳过 LLM 调用；实现转人工判断——独立 LLM 分类用户意图（明确拒绝 / 非本人 / 要求人工等），命中时向通话平台发送转人工信号。

### 3. 会话管理模块

外呼通话期间高频读写上下文（对话历史、当前阶段、规则命中记录等），基于 OrderedDict 实现 LRU 会话池，访问时提升至最近端，TTL 超时淘汰 + 容量上限淘汰双重保障，后台线程定期清理，对话结束时主动释放资源。

### 4. 引擎抽象与协议适配

定义工厂接口 + 连接接口两层抽象，各引擎（FunASR / JD / Decoder）独立实现各自的协议适配，新增引擎仅需实现标准接口即可接入。

### 5. 流式会话管理

为无状态 HTTP 引擎设计多包会话协议，每包均增量识别并返回结果，首包建立会话状态，末包结束释放；支持标准 / 自动断句 / 长语音三种识别模式；定期清理超时会话；全局并发计数器控制会话数上限。

### 6. 流量路由与平滑迁移

设计流量路由层，支持多引擎混部与灰度发布：加权随机选择下游实例，实例下线时拒绝新会话但存量会话继续直至完成，多包请求通过会话映射保证同一请求亲和同一实例；动态配置热加载支持 VAD 阈值、引擎参数等即时生效，变更失败自动回滚。

### 7. 压测成果

ASR 服务 100 并发压测平均尾包延迟 127ms；50 并发 P90 尾包延迟 116ms，较旧服务降低 58%。
