⚠️ 致命短板&面试高风险点（面试官一定会抓着拷打，也是扣分项）
1. Agent部分高度依赖LangGraph框架，容易被质疑“框架使用者，而非设计者”
简历大量能力建立在LangGraph之上：Checkpointer、interrupt HITL、State状态流转。
面试官高频灵魂拷问：
- 如果不让你用LangGraph，让你手写一个简易Agent状态机，你怎么做？
- LangGraph的Checkpointer、interrupt底层有什么缺陷，生产环境会踩什么坑？
- 如果框架替换成自研状态机，你的三层上下文架构还能不能复用？

风险：如果你只会调API，不懂底层实现，会直接降档。

2. Agent核心短板：缺少记忆系统（长时记忆、向量记忆、RAG结合）
你的简历完全没有涉及Agent长时记忆、向量库、RAG工具链。
你解决的是会话内短时上下文优化（三层上下文），但是Agent另一大核心模块：持久化记忆、向量检索记忆、记忆的压缩/摘要，简历完全空白。
面试官会直接提问：你们业务为什么没有做长时记忆？如果要给Monet画布Agent增加长期记忆，你会怎么设计？

3. HITL只做了工具执行阶段的中断审批，缺少Agent输出侧的校验、对齐
你实现的是工具调用高危动作拦截审批，但是没有做：Agent输出结果校验、输出对齐、拒绝有害输出、工具调用纠错（Agent调用错工具、参数错如何自动修正）。
工业Agent很大一块工作量就是处理LLM输出不稳定，这块简历体现不足。

4. 分布式调度与Agent业务的耦合讲的弱
现在简历是两个独立模块：上层Agent业务层、下层调度平台。面试官会追问：
Agent调用图像/视频生成工具，如何和你自己写的这套分布式调度平台打通？
Agent侧如何处理调度侧任务排队、失败、重试、供应商切换？
Agent Graph内部怎么集成任务异步回调？

简历没有体现上层Agent和底层调度平台交互链路，看起来两块是分开做的，如果你讲不清楚打通逻辑，会被认为两个模块只是分别干活，缺少端到端全局视角。

5. 工程上部分方案带有明显原型痕迹，面试官会挑战生产可行性
- Checkpointer使用SQLite做持久化，这在生产多实例部署是硬伤。面试官一定会攻击：多实例部署，SQLite文件本地存储，实例漂移后Checkpoint丢失，生产怎么解决？
- ContextVar做会话隔离，Asyncio下边界、嵌套、子任务泄漏，会深挖线上踩坑。
简历写的是你实现的方案，但是你必须主动讲清楚：原型方案的局限，以及真正生产环境该如何改造。只讲优点不讲局限，会被扣分。

6. 缺少压测、性能数据
Agent服务：单实例支持多少并发会话？SSE长连接上限？调度平台峰值QPS、任务并发数。现有指标偏向业务收益，缺少系统压测数据。
