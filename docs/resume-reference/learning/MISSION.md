# Mission: 学 DM 项目，写出能撑住面试的简历

## Why

27 届秋招投 AI Agent 开发/算法岗。DM（Monet + Scheduler）是简历上最重要的两个项目，但目前对架构和实现细节掌握不够，面试被追问就露馅。目标是**能画出架构图、讲清楚模块协作、并从 GitLab MR 里挑出 8-10 个有含金量的具体工作作为"我做的"，做到能 defend 到深处**。

## Success looks like

- **架构层面**：能在白板上画出 Monet 和 Scheduler 的整体架构图，讲清楚各模块职责、数据流、关键设计权衡
- **具体工作**：从两个项目各挑 4-5 个有含金量的 MR/功能，能讲清楚"为什么这么做、遇到什么问题、怎么解决的、效果如何"
- **量化数据**：每个亮点都有具体数字（QPS、延迟、任务量、成功率等）
- **面试防守**：面对"这个模块为什么这样设计"、"如果 XX 情况怎么处理"、"和 YY 方案对比优劣"等追问能自然应答
- **简历产出**：两份简历（开发岗 / 算法岗）里的项目描述都能对应到具体的技术实现

## Constraints

- 时间：秋招在即（约 2-3 个月），学习节奏要紧凑
- 深度取舍：不需要吃透每一行代码，但每个"亮点"必须能 defend 到 3-5 层追问
- 学习方式：偏应用型，不追求纯理论深度
- 项目现状：Monet Agent 参与度不深，需要通过 GitLab MR 补充；Scheduler 参与度更高但架构未全懂
- 双线并行：Monet 和 Scheduler 同时学，不串行

## Out of scope

- 前端相关（Monet 客户端 UI 层）
- 深入 dmfr 脚手架内部源码（会用就行，不深挖）
- 讯飞 GRPO（另立工作区）
- 从头做个人开源项目（时间不允许）
- Kubernetes/运维底层（了解概念即可）
