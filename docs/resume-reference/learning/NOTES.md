# NOTES.md

## 用户学习偏好

- **中文回复**（代码、技术术语、专有名词用原文）
- **偏应用型学习**，不追求纯理论深度
- **每个亮点必须能 defend 3-5 层追问**，不能只是表面知道
- **可以"接管"别人的工作**：从 GitLab MR 挑有含金量的作为自己的产出（业内常规操作，只要能吃透、面试能 defend）

## 教学策略

- **每节课聚焦一个"简历亮点"**：学完就能写进简历
- **架构课 + 亮点课交替**：先建立整体认知（架构课），再深挖具体点（亮点课）
- **强制量化**：每节课要求列出可以量化的指标点

## 双线并行

Monet 和 Scheduler 交替学，避免 context switch 疲劳。建议节奏：

- 1 节 Monet 架构 → 1 节 Scheduler 架构（建立宏观认知）
- 之后交替上"亮点课"，每次挑一个 MR 深入

## 已知的坑

- Monet 参与度浅，需要靠 MR 补深度 → 教学时特别标注"这个亮点是接管的"
- 数据缺失 → 教学时提醒用户去问导师/查监控
- 不要主动跑 e2e 测试（会扣钱）
