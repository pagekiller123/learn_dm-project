# 技术方案 vs 实际代码：双层记忆策略

学员发现《DreamMaker Agent 技术方案》里描述的架构（如"DM CLI 层"）跟实际代码（<code>DmApiBackend</code> HTTP 封装）不完全对应，担心该记哪个。确定策略：**分层记忆**——宏观架构和设计意图记官方方案（稳定不变），具体实现细节记当前代码（易变），Roadmap 里未落地的能力两个都记但讲的时候明确划分。

## 为什么

- Monet 还在持续开发，代码今天写、明天可能重构。但**设计意图和五层骨架是团队多人共识 + 长期不变**——就算 <code>DmApiBackend</code> 明天改名，"DM CLI 层负责所有后端通信 + 认证 + Token 优化"这个抽象层还是这个抽象层
- 面试官更愿意听到有骨架的人，而不是背了一堆已经变化的代码路径的人
- 反过来，如果只讲方案，面试官追问"具体在哪个文件、什么函数"你答不上来，就露馅了

## 具体规则

1. **画架构图**：用官方五层骨架 + 标注"当前代码实现"（Lesson 0001 已用图 A + 图 B 双图形式实施）
2. **讲"我做了什么"**：只讲代码里真实存在的东西
3. **被问到"能不能做 X"**：如果官方方案里规划了但代码没实现，说"团队有规划（引 vision），当前实现还没做到"
4. **被问到"为什么这么设计"**：引官方方案里的权衡（CLI vs MCP 的 Token 消耗对比、客户端 vs 云端 RTT 优势）

## Implications

- Lesson 0001 已经改成双图形式，加了 Harness Artist 品牌概念和 DM CLI 层的面试防守话术
- 后续新 Lesson（0002 及以后）也应按这个模式：先讲设计意图，再讲当前实现，两层都要清楚
- 遇到"文档 vs 代码冲突"时，我（教师）不再默认以某一方为准，而是主动区分讲清楚
- 长期建议：秋招期间**每隔几周重跑一次 <code>src/monet/</code> 结构对比**，确保图 B 跟实际代码同步
